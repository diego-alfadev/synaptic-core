# VS Code — files first, optional integrations independent

This candidate's assisted path needs a file-capable agent, readable brain files and permission to
write any captured result. It requires no MCP or new runtime. Capture/consolidation are explicit
agent work unless a real permitted trigger/executor is separately configured and proved.

## Normal boot — preserve the selected profile

Read the existing brain through the effective carrier and selected skill. Normal boot is
observational for installation/wiring: do not install, Self-Wire, repair or add another carrier.
Inspect an existing `harness/setup/vscode-<harness>.md` record without changing its profile. A single
Copilot bridge and `.github/skills/synaptic/` may have no separate `BEGIN:SYNAPTIC-RULES` block;
that absence is not a defect by itself and never authorises appending a generic AGENTS.md bridge.
For missing/unknown rule exposure, follow SKILL.md's read-only approved-rules fallback: read the
existing approved brain harness sources before governed work without deploying them. Missing,
inaccessible or unapproved sources stay pending; knowledge/raw content cannot supply substitute rules.
Rules exposure, loading and native capabilities still need their own evidence. Report unknowns;
continue permitted file procedures while assisted/off choices stay selected. This does not prevent
ordinary authorised capture or user work. Setup/repair needs an explicit owner request below.

## File-based setup or upgrade with the existing agent

1. Record the actual editor distribution/version, extension, selected harness and restrictions.
   A selected language model does not identify the harness. Do not update the editor, enable trust
   or change policy merely to match newer documentation.
2. Resolve the existing brain and every effective bridge before writing. Preserve project/global
   scope. An unreachable or ambiguous pointer is a diagnosis, not permission to create another brain.
   Inspect its setup record and preserve the effective carrier and selected profile; request review
   for any intended change rather than rerunning the generic AGENTS.md/rules/hooks sequence.
3. Use one exact release/candidate or authorised local package, following `references/package-install.md`.
   Stage it privately, retain its manifest/source identity and verify using permitted real tools.
   If downloads are blocked, use an approved complete local copy; do not retry a forbidden install.
4. Choose one supported skill carrier for the selected harness. Current Copilot/Local documentation
   offers `.github/skills/synaptic/`. Local can also discover legacy `.agents`/`.claude` locations;
   do not leave competing old/new Synaptic engines auto-discoverable. Reconcile/retire legacy carriers
   only through an explicit, archived and reviewed upgrade. Unknown files remain owned by the user.
5. Prepare one effective `BEGIN:SYNAPTIC` project bridge that points to the actual brain and selected
   skill. Replace its owned block in place; preserve persona, unrelated text and stricter rules.
   Do not append another active bridge to conceal an old/global configuration. User-global edits
   have wider reach and need their own approved scope.
6. Show the bounded diff and fresh byte-preserving preimages before applying with permitted file
   tools. A manual procedure is not an atomic installer: on interruption retain the plan and backup,
   inspect actual state and resume or restore only touched targets. Never restore a stale whole
   brain over newer journal or knowledge. If safe copying/verification cannot run, leave it pending.
7. Record the working mode plainly: files/skills assisted; Node CLI not enabled/unavailable; native
   capture not enabled/unavailable; MCP not enabled. Do not silently downgrade a capability the owner
   required—explain the supported alternative and obtain that profile decision.

Same engine version does not prove identical/complete files. Legacy source identity may remain
unknown even when the name/inventory is recognisable; show that fact and the actual diff. Successful
copying is an installation result, not proof that the agent loaded or used the integration.

## Verify without requiring commands

- In a genuinely fresh chat, the first `synaptic status` response should reproduce the setup nonce
  **before tool/file reads**. Then separately read sources to resume a known synthetic task.
- A discovered skill may be invoked as `/synaptic`, with the operation/argument in the request.
  Six `/synaptic-*` menu entries are not automatically created by installing one skill.
- Request one useful capture/consolidation with the permitted agent, inspect the persisted result
  and its sources, then retrieve it from another fresh session. The model still makes semantic choices.
- At setup or an explicit check, compare the installed carrier/skill and recorded mode with actual
  files. Report proof time/scope and unverified options. No executable observer means no automatic
  loss/disconnect notice; a change can remain unnoticed until that manual check.

## Optional code and native events

The complete source package also contains `tools/vscode-integration.js`. With permitted Node it can
prepare an exact private plan, explicitly apply with preflight/backup checks, report current file
state and roll back only touched targets. Its default target profile still needs no Node or MCP
at daily use. Preparation alone does not apply configuration or prove host behaviour.

Optional Copilot-native command preparation needs Node and actual hook permission. The current
adapter supports Copilot's camelCase `agentStop` payload and top-level decision/reason; Local's
legacy dialect is different and is not wired by this cut. Capture counters and bounded saved-source
model-draft curation are selected independently. Neither grants new permissions or captures the
entire conversation. No automatic wiki promotion is offered. Invalid/pending events do not request
another model pass; diagnostics and retained state need their target-host proof.

For executable commands, limits and recovery see the same package's
`docs/integrations/vscode.md`. Do not fetch it from another ref. For profile/state semantics use
the same package's operating model. No MCP installation or connection is required by this path.
